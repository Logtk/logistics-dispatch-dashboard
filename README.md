# 配車手配 潜在ロス分析ダッシュボード（logistics-dispatch-dashboard）

同じ配送データを使って、「今のやり方」と「配送をまとめて効率化した場合」で運賃がどれだけ変わるかを見比べられるデモです。

## 背景と解決したい課題（Why）

配送先ごとに個別に車を手配していると、車の空きスペースや便数に無駄が出ていることがあります。この無駄は感覚的には理解されていても、「どの段階でどれだけ削減できるのか」を段階的に切り分けて示すツールは現場に少なく、削減余地が定量化されないまま放置されがちです。このダッシュボードは、同じ配送実績データに対して3つの段階でシミュレーションし、どこまで削減できるかを一目で示すことで、この定量化の空白を埋めます。あわせて大手宅配便との想定金額比較を置き、自社便が価格競争力を持てているかどうかも合わせて確認できるようにしています。

## 機能概要とアーキテクチャ（What / How）

Vite + React / Tailwind CSS / Rechartsで構築しています。同じ配送実績データに対し3段階のシミュレーションを適用し、それぞれの運賃を比較します。

1. 🔴 **今のやり方** — 依頼ごとに個別で車を手配した場合の運賃(現状)
2. 🟡 **積み合わせた場合** — 同じ日・近いエリアの配送をまとめて1台に積んだ場合の運賃
3. 🟢 **曜日をまとめた場合** — 配送する曜日を週2回に絞り、便数自体を減らした場合の運賃(車のサイズアップ分も加味)

走行距離はGPSの実測値ではなく、配送実績から推定した目安の距離です。

### 動かし方

```bash
npm install
npm run dev
```

ブラウザで`http://localhost:5173/logistics-dispatch-dashboard/`を開くと表示されます。本番ビルドの確認は`npm run build && npm run preview`。デモ: https://logtk.github.io/logistics-dispatch-dashboard/

## 誰のためのツールか、どう自分たちに応用するか

**対象読者**: 自社便を持ち、大手宅配便との価格競争力を経営層に説明する必要がある物流拠点の配車・営業企画担当。

**応用方法**: `RATE_MASTER`(車格別運賃)と配送実績データ(`SHIPMENTS`)を自社の実際の車両運賃・配送実績に置き換えるだけで、3段階シミュレーションと大手宅配便比較を自社データで再現できます。既に配車システムを持ち積み合わせ最適化まで実施済みの拠点にとっては、このツールが示す削減余地はほぼ顕在化済みのはずで、その場合は`Deliv_arrangement`のようなより精緻な最適化ロジックとの比較検証に使う方が価値があります。

## 現在のステータスと直面している課題（Current Status & Technical Challenges）

3段階のシミュレーションと大手宅配便比較まで、一通り動作する状態まで実装が完了しています。実装にあたって意図的に単純化した点を明記します。

**構造的課題: 走行距離が推定値であること**

走行距離の算出は実測のGPS・ルート探索エンジンによるものではなく、配送実績データからの推定値です。実際の道路網・渋滞・時間帯による所要時間の変動までは反映していません。まず「積み合わせによってどれだけ削減余地があるか」という規模感を経営層に示すことを優先し、精緻な経路計算はあえて次のステップとして切り分けた設計判断です。

**構造的課題: 最適化ロジックが決め打ちのビジネスルール**

3段階のシミュレーションは「同じ日・近いエリアをまとめる」「曜日をまとめて便数を減らす」という決め打ちのルールに基づいており、`Deliv_arrangement`で実装したような貪欲法+ヒューリスティックによるVRP近似解ほどの最適化は行っていません。より単純なルールベースの比較に留めているのは、経営層向けに「なぜ削減できるのか」を直感的に説明できることを優先したためです。

## 今後の展望（Next Steps）

- 実際の道路網データ(例: OSRM等のオープンソース経路探索エンジン)と接続し、走行距離・所要時間の精度を高める。
- `Deliv_arrangement`のVRP近似ロジックをこちらのReactベースの可視化基盤に統合し、より高度な最適化シナリオも同じUIで比較できるようにする。
- 大手宅配便との比較ロジックに、荷姿・重量帯別の実際の運賃表を組み込み、比較の精度を上げる。強いエンジニアリングやLLMを使ったデータ収集・整形との協業で取り組みたい領域です。

## データについて

画面内のデータ(納品先・手配実績・金額など)はすべてダミーデータです。実在の企業・取引・金額とは一切関係ありません。
